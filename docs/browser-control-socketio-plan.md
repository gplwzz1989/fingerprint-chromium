# 方案二：统一使用 Socket.IO 控制独立环境

日期：2026-10-05。状态：方案计划，尚未实施，尚未选择为项目执行方案。

目标：SaaS、同机外部程序和远程调用方统一通过 Socket.IO 控制 Chromium。页面宿主只承担显示与固定控制台职责，浏览器控制连接由原生维护，DOM、网络和原有本地能力共用版本化控制契约。

本文件与 [方案一：保留 postMessage 并增加 Socket.IO](browser-control-hybrid-plan.md) 是互斥的最终架构选择；迁移期可以暂存旧桥，最终控制调用不再经过 postMessage/MessagePort。制定计划不授权改编译参数、安装依赖、全量构建、部署或发布；遵守 [开发规则](development-rules.md)、[开发计划](development-plan.md) 与 [AGENTS.md](../AGENTS.md)。

## 1. 当前事实与迁移范围

本次核对对象为仓库源码和协议，没有完成最新 Windows 程序或 Android APK 的本方案运行验证。

| 当前项目 | 迁移目标 |
| --- | --- |
| PC SaaS 依赖 iframe postMessage →固定 WebUI → C++ | SaaS 以 Socket.IO 客户端访问本机端点；WebUI 不再转发控制指令 |
| Android SaaS 依赖主框架 MessagePort → Java/JNI | SaaS 访问应用内本机 Socket.IO 端点；原生连接不随页面刷新销毁 |
| 外部程序没有独立控制入口 | 本机与远程统一契约、鉴权、请求结果和事件订阅 |
| tabs/storage/fingerprint/files/http/crypto 已有源码 | 最小迁移到公共执行入口，保持业务语义和平台能力声明 |
| DOM/页面网络读取未实现 | 增加原生 DOM 判断、等待、请求/响应事件及正文读取 |
| PC http.request 不按 tabId 选择独立分区 | 修复主动请求分区路由，不能把旧路径包装为已隔离能力 |

现状依据：[Web 桥客户端](../saas-web/bridge-contract.js)、[类型契约](../saas-web/bridge-contract.d.ts)、[桥协议](saas-bridge-contract.md)、[Android 平台模块](../android-bridge/README.md)。PC 原生实现位于展开源码的 `chrome/browser/ui/webui/management/management_ui_handler.cc`、`chrome/browser/managed_tab/` 等实际调用入口。

范围包括全部浏览器控制调用的迁移，但不迁移 Go 登录/目录/快照 REST API，也不把 SaaS 业务放入 Chromium。常驻控制台和单账号单活跃 Tab 继续保留，统一通信不自动改变外壳设计或授权配置。

## 2. 目标架构与部署路径

```text
同机 SaaS / 外部程序 ── Socket.IO ──→ Chromium 本机控制端点
                                              ↓
                                        统一原生控制服务
                                              ↑
远程 SaaS / 外部程序 → Go 控制网关 ⇄ Socket.IO 原生客户端
                                              ↓
                                    账号对象 / DOM / 网络 / 存储
```

- 本机端点由原生生命周期管理，仅绑定回环地址；Windows 浏览器进程和 Android 应用各自实现平台挂接。UI 加载不是服务启动前提，页面不能持有端点的唯一连接。
- 原生远程客户端主动连接受信网关，远程控制不需要开放设备公网端口。Go 保留现有业务鉴权，新增设备连接、账号授权和命令路由；不复制登录业务进原生。
- 同机调用直接走回环端点，断公网时不绕云端。云端身份失效后，本地授权不能自动扩权；已打开 Tab 仍可正常浏览。离线管理仅限有效本地授权及现有本地对象，不伪造云端账号目录或权限。
- 外部程序可直接使用同一契约，DOM/网络操作与 SaaS 的页面、窗口及脚本生命周期无关。
- 控制面连接独立于账号代理/Cookie，不能因切换被控账号代理而改变控制网关身份或出口。

### 2.1 本机服务端是必需交付项

此方案以原生内集成本机 Socket.IO 服务端为目标，不假定官方 C++ 客户端能提供监听服务。官方 C++ 客户端 3.x 支持服务端 3.x/4.x，依赖 websocket++，只实现 WebSocket transport；它仅是远程连接的候选。[C++ 客户端说明](https://github.com/socketio/socket.io-client-cpp)

B0 必须验证服务端方案：基于 Chromium 现有网络能力实现受限 Engine.IO/Socket.IO 协议适配，或引入已验证、可维护的原生依赖。验证握手、心跳、namespace、事件、二进制、ack、错误关闭、TLS 和 JS/外部客户端互通，不只验证“WebSocket 连上”。目标为 Socket.IO 4.x / Engine.IO 4，统一使用验证过的 WebSocket transport，不默认声称轮询回退可用。[协议说明](https://socket.io/docs/v4/#what-socketio-is-not)

Go 网关实现同样须独立验证，不能直接采用已归档且仅声明支持 JS 客户端 1.4 的 googollee/go-socket.io。[仓库说明](https://github.com/googollee/go-socket.io)

本机服务端未通过时，本方案停留在选型阶段，不移除旧桥；“只连云端”会失去断公网的本机控制能力，不作为默认替代。独立 Go/Node 网关属于另一个部署变体，需要单独评估进程维护、安装升级及 Android 可行性，本计划不自动引入。

### 2.2 SaaS 访问回环端点的接入条件

1. 定义端点发现和配对流程：固定入口或受信启动配置提供端点信息，用户或受控启动完成一次性配对，换取短期、最小权限令牌；凭据不放 URL、页面日志或普通持久化存储。
2. HTTPS SaaS 到回环端点的证书、Origin、CSP connect-src、浏览器本地网络访问策略必须在实际 PC/Android 上验证。正式接入使用可信 WSS，不用关闭 TLS/混合内容检查或放宽全局来源规则解决问题。
3. 端口绑定失败、证书失败、首次配对、令牌过期和浏览器未启动分别返回中文状态。不能以空 Tab 列表冒充成功连接。
4. 远程浏览器里的 localhost 是调用方自身，不是目标设备。前端显式选择“本机设备”或“远程设备”，远程路径通过网关路由，不按域名或 UA 猜设备。
5. Android 端点的创建/销毁与应用生命周期绑定，Activity 重建不复活旧配对授权；进程回收后端点/连接代次变化，客户端重新发现和验证，不保证后台永久在线。

## 3. 一套控制契约与原生执行服务

以下均为拟新增或迁移的契约，不表示已实现。控制契约版本独立于 Socket.IO、Engine.IO 和快照 schema_version。

| 对象 | 定义 |
| --- | --- |
| 调用身份 | 本机显式配对或经 Go 授权的远程调用方，包含作用域、有效期及授权/连接代次 |
| 请求 | protocolVersion、requestId、deviceId、accountId、environmentId、documentGeneration、method、args、有效期限 |
| 环境标识 | 原生分配的本次运行环境标识，映射 accountId、内部 tabId、WebContents；重开变代次，不作为跨设备账号身份 |
| 时限 | 网关限制命令存活，原生接收后使用单调时钟判定本地截止时间，避免只比较未校准设备时钟 |
| 响应 | 区分已接收、执行中、已完成、失败、取消和结果待确认；中文 message、稳定 errorCode、相关 requestId |
| 事件 | subscriptionId、环境/文档代次、sequence、种类、必要元信息和缺口/结束标记 |
| 能力 | 各平台真实方法、对象覆盖、额度、正文格式、订阅恢复范围和版本；未实现时明确不可用 |

Socket.IO 事件封装与业务指令分开。统一用 control.request、control.response、control.event 承载消息，具体动作写在 method 中；外部 SDK 与 SaaS 使用同一校验规则。异步事件独立于 ack，ack 表示接收还是最终结果须固定，不让不同客户端自行猜测。

### 3.1 交付能力

| 能力 | 计划接口与约束 |
| --- | --- |
| 标签页 | 迁移 tabs.list/create/activate/navigate/close；保持账号幂等、控制台保护及原生状态查询 |
| DOM | dom.query/check/waitFor，按 frame/选择器读取和判断，明确数量、可见性、文本/属性条件和等待取消 |
| 网络 | network.subscribe/unsubscribe，推送 request/response/finished/failed；正文由 getRequestBody/getResponseBody 按需读取 |
| 存储与指纹 | 迁移现有快照读写、fingerprint.get/set；保留选类别、同值恢复/回读、原生串行和部分失败语义 |
| 系统能力 | files、crypto、secureStorage 仍按平台能力和系统权限执行，不把 Socket.IO 连接视为文件/密钥授权 |
| 主动 HTTP | http.request 与页面监听分开，账号凭据只取真实目标独立分区，PC 漏实现须修复 |

DOM/网络复用 DevTools 必要域，但不开放任意 CDP 或任意 JS 执行。主框架、跨源/OOPIF、Shadow DOM 及四类 Worker 的覆盖逐项声明；无法归属账号的共享目标不授予读取。DOM 节点/frame 绑定文档代次；请求键组合 target/session、订阅代次、requestId 和重定向跳数，不能只用 requestId 查全局缓存。[DOM 协议](https://chromedevtools.github.io/devtools-protocol/tot/DOM/)、[Network 协议](https://chromedevtools.github.io/devtools-protocol/tot/Network/)

默认网络事件仅包含必要元信息，头与正文单独授权；正文缓存按账号/订阅隔离，设有效期和内存额度。开始订阅前的历史流量、文件上传、流式响应、下载、SW 缓存和 WebSocket 帧分别明确覆盖与限制。无法读取正文须返回原因，监听不得改变页面代理、缓存、SW 或实际网络执行。

## 4. 授权、可靠性与隐私

- 本机与云端都需要鉴权。Origin/CORS、namespace/room、回环地址和设备在线状态都不能代替账号权限；每条命令在网关和原生执行前分别检查其授权边界。
- 原生不信任消息自报角色；使用受信控制服务授予的短期、设备/账号/动作范围授权，本机配对走独立作用域。调用方和设备重连后重新验证，旧代次命令不得执行。
- 同账号修改进入一个原生队列，查询绑定真实文档；导航、关闭、冻结、权限失效后取消关联等待/订阅。连接取消不能自动撤回已经发送的网站请求或已经完成的部分写入。
- 命令去重绑定调用身份、requestId/操作标识及参数摘要；记录未决/终态，提供结果查询。丢失应答不能自动重复创建、恢复、关闭或 POST 导航，进程重启后的去重边界须明确。
- Socket.IO 的自动重连不保证事件必达。使用有界序列缓冲、续传游标和明确缺口通知；未实现跨进程持久化则不承诺重启后事件恢复。[交付保证](https://socket.io/docs/v4/delivery-guarantees/)
- 命令、事件和大正文分别设队列/优先级与额度；大数据分块带长度/校验、取消、过期及释放规则。慢客户端不能无限占内存，线程调度不能阻塞 UI/TabModel。
- 云端仅保存已有客户端加密快照和必要控制元数据。敏感 DOM、正文、Cookie、代理凭据和快照密码通过调用方到原生的加密封装转发，不写入网关普通字段或日志；授权封装绑定动作/目标/期限，解密后再次核对，不把“加密”当作授权。
- 本机敏感传输用已验证的受保护连接，系统文件与 Keystore 继续保留原生授权。迁移 crypto 或 secureStorage 不允许持久化快照密码、同步设备密钥或静默回退明文。
- 退出 SaaS、设备会话撤销或账号失权后停止对应云端操作/推送及在途后续副作用；保留已打开本机账号 Tab 浏览，不关闭、不清空、不切换共享分区。失效云端身份不自动转成本地长期令牌。

## 5. 迁移步骤与实施定位

所有阶段当前待开始；迁移期的双入口仅为兼容措施，不能同时产生两套执行状态。

| 阶段 | 工作与交付物 | 出口条件 |
| --- | --- | --- |
| B0 可行性与基线 | 本机原生服务端、C++ 远程客户端、Go 网关、Web/外部客户端互通；HTTPS→回环接入、Android 生命周期与依赖评估 | 本机/远程都能真实握手及应答；选型、风险、编译影响有证据；不通过则保留旧桥 |
| B1 公共控制服务 | 最小提取现有能力分发、环境注册、授权、队列、取消和结果查询；维护公共契约与类型 | 同一执行入口；PC/Android 同语义；未实现 capability 为 false |
| B2 DOM/网络能力 | 真实对象与 DevTools 目标挂接、条件等待、过滤、订阅和正文；补 PC 主动 HTTP 分区 | 双账号真实 DOM/网络隔离与导航失效通过；目标覆盖和限制有记录 |
| B3 原生通信与网关 | 本机 Socket.IO 服务端、原生远程连接、Go 路由/授权、配对、加密载荷、去重与背压 | UI 未加载时控制服务可用；授权过期/断线不复活操作；同机调用不依赖云端 |
| B4 SaaS/SDK 迁移 | 在 saas-web 增加统一控制客户端适配，迁移现有调用、事件、能力显示与错误；提供同契约外部接入说明 | 标签页/存储/指纹/文件/HTTP/加密/会话流程均走新入口；无页面转发依赖 |
| B5 新产物与验收 | 按批准范围完成两端局部检查、平台产物及真实性能/安全/同步回归 | 第 6、7 节必要项逐端通过；HTTPS、本机和远程接入都有真实证据 |
| B6 切换与兼容收口 | 默认使用 Socket.IO；版本/能力显式选择，停用旧桥控制分发；保留历史实现及回退记录 | 无自动双通道重试；旧客户端明确兼容/升级要求；固定控制台可用 |

现有文件最小修改：Web 桥封装、app/operations/snapshot-sync/session-persistence 的相关调用；Go httpapi/auth/config 和必要路由模块；PC WebUI 与账号本地能力；Android SaasBridgeHost、分发器、TabModel/JNI 对应挂接。新增通信模块的位置在 B0/B1 确定，源码、模块副本与可重放补丁同步，新增补丁登记 patches/series。

最终 SaaS 获取浏览器能力不再依赖向 WebUI 发消息，但 WebUI/Android 外壳可以继续加载业务页面。迁移完成后移除的是活跃控制分发职责，不是未经确认删除所有历史文件或注释。接口破坏性变化需递增主版本，旧快照格式与账号分区不因控制协议版本变化重建。

### 5.1 切换与回退策略

以客户端已确认能力与配置显式选择通道，每次操作开始后固定传输和授权上下文。Socket.IO 超时先查询结果，不自动用 postMessage 再执行同一动作；迁移期旧桥也进入统一队列和去重服务。

回退单位是控制客户端/入口版本，不是环境数据。B6 前可回退旧入口，B6 后保留经验证的版本回退程序，不在运行时偷偷恢复旧桥。回退必须停止新订阅、清理连接授权及未完成队列，保留真实账号分区、密文、系统授权与结果记录；不能把不可回退的新副作用说成已撤销。

## 6. 性能与资源验证

本方案不以 Socket.IO 比 postMessage 更快作为立项依据。预期收益是统一接入和连接生命周期；是否满足本机性能要求必须测量。

1. 使用迁移前现有桥作为基线，对比本机 Socket.IO 与经网关的远程 Socket.IO；保持同一原生服务、同一真实页面、授权、过滤和正文策略。
2. 分别测端到端 p50/p95/p99、传输/序列化、队列等待、原生执行和回调耗时、完成量、错误/超时、CPU、内存、字节量与事件缺口。跨设备用往返或单端单调时钟，不拿未同步时钟相减。
3. 提议独立测试梯度为 1/5/10 个环境、1 KiB/64 KiB/1 MiB 载荷，测 DOM 查询、原生 waitFor、突发网络元事件及按需正文；梯度不是支持承诺，Android 按设备资源限制并验证显式拒绝。
4. 分开测回环与公网，前台空闲与页面繁忙，开启与关闭监听。网络延迟不能算作 Socket.IO 编码性能，也不能用不同批量策略证明某个传输更快。
5. 验证大正文不会饿死普通控制指令，慢消费者内存有上限、溢出可见；检查监听不改变页面加载、缓存/SW 与网站网络行为。
6. Android 补测前后台、Wi-Fi/移动网络切换、锁屏、Activity 重建、进程回收和耗电；不承诺无限后台保活。长连接的移动端耗电与后台限制需单独评估。[官方移动后台说明](https://socket.io/docs/v4/#what-socketio-is-not)
7. B0 记录真实测试设备、运行产物及基线，B5 首轮形成可复测数值门槛；本次不编造速度倍数或固定延迟。安全门槛为零串账号/越权/过期执行，超限、缺口与未知结果必须可见。

## 7. 验收与完成定义

| 场景 | 通过条件 |
| --- | --- |
| UI 独立 | SaaS 未加载、刷新或关闭时，其他有效调用方仍能读 DOM/网络；原生端点不依赖页面脚本 |
| 本机离线 | 公网断开时，有效本地授权仍可管理已有本地对象；云端业务明确不可用，不伪造目录或权限 |
| 端点与配对 | 可信 WSS、来源/本地网络策略通过；端口失败/无配对/令牌过期有中文错误，不开放无鉴权接口 |
| 两账号同来源 | DOM、iframe/Worker 目标、网络事件、正文、Cookie、代理和主动 HTTP 不串账号 |
| 导航与旧对象 | 文档/frame/node/订阅/正文句柄过期后拒绝；新文档不接收旧命令副作用 |
| 断线与重连 | 查询真实状态、重新授权和订阅；无盲目重放；内存有界、缺口明确、结果未知可查询 |
| 退出及撤权 | 对应云端指令/数据推送停止；本机 Tab 继续网站浏览，旧身份不转为新的长期本地授权 |
| 原有闭环 | 账号创建/切换、存储类别、客户端加密、版本/租约、严格指纹恢复/回读及 SAF/Keystore/文件能力真实回归 |
| 双端产物 | 最新 Windows Release 与 Android APK 各自运行验收；Android 设备生命周期结果不能用 JVM 或 PC 结果代替 |
| 完全迁移 | SaaS 与外部调用共用契约，所有活跃控制动作不再经 postMessage/MessagePort；历史实现与回退边界可追溯 |

文档、协议互通、局部语法、目标编译、最新产物运行和可发布分别记状态，不互相代替。全部编码完成前不启动全量构建；任何编译参数变更先报告具体旧值/新值、两端输出及重编译源文件/编译单元、生成/链接目标数量估算。Android 构建仅走已核实的 WSL Linux 工具链；完整保留 build/publish 和各平台缓存，本次不执行 GN/Ninja。

## 8. 与方案一的选择依据

| 决策项 | 方案一：保留本地桥 | 方案二：统一 Socket.IO |
| --- | --- | --- |
| 本机交互 | 保留当前路径，通常传输开销较低，待实测 | 所有控制增加 Socket.IO 路径，须对照基线 |
| 页面宿主耦合 | 内嵌调用仍有；外部控制独立 | 活跃控制不再依赖宿主，显示外壳仍保留 |
| 维护成本 | 两种适配器、跨通道授权/队列及一致性 | 一个传输体系，本机服务端/TLS/配对及全量调用迁移成本更高 |
| 离线能力 | 原桥可继续本地调用 | 必须交付本机端点，不能只依赖云端网关 |
| 风险与回退 | 新能力可逐步开放，旧路径容易保留 | 本机端点成为控制入口，故障影响面更大，需先完整迁移回归 |

本方案适合将独立浏览器控制 API 作为长期主入口、愿意承担本机端点与迁移成本的方向。两份方案的 DOM/网络、安全、执行模块和性能测试成果可复用，但最终是否保留本地桥应明确选择，不能把两个互斥终态同时登记为已实施。
