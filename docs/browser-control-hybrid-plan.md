# 方案一：保留 postMessage，增加 Socket.IO 控制通道

日期：2026-10-05。状态：方案计划，尚未实施，尚未选择为项目执行方案。

目标：保留内嵌 SaaS 的本机调用路径，为外部程序和远程控制增加 Socket.IO；两种传输共用一套控制契约和一个原生执行模块，提供独立环境的 DOM 查询、条件判断、网络请求及响应读取。

本文件与 [方案二：统一 Socket.IO](browser-control-socketio-plan.md) 是互斥的最终架构选择，可以共用前期契约和原生能力建设成果。制定计划不授权改编译参数、安装依赖、全量构建、部署或发布；实施继续遵守 [开发规则](development-rules.md)、[开发计划](development-plan.md) 与 [AGENTS.md](../AGENTS.md)。

## 1. 当前事实与目标差异

本次核对对象为仓库源码和协议，不是最新 Windows 程序或 Android APK 的运行验收。

| 项目 | 当前事实 | 本方案目标 |
| --- | --- | --- |
| Windows 页面入口 | SaaS iframe → postMessage →固定 WebUI 宿主 → C++ | 保留入口，宿主只校验来源并转发统一控制契约 |
| Android 页面入口 | 主框架 MessagePort → Java 宿主 → JNI/C++ | 保留真实端口授权与生命周期，转发同一执行模块 |
| 现有能力 | tabs、storage、fingerprint、files、http、crypto；secureStorage 按平台声明 | 原有业务流程继续使用真实能力；新增 DOM 和网络订阅能力 |
| DOM 与页面网络 | 现有桥没有 DOM 查询或页面网络监听接口 | 两种传输访问同一账号 WebContents，执行查询与订阅 |
| 主动 HTTP | PC 的 http.request 使用 Profile 网络工厂，没有按 tabId 选择账号分区；Android 已编码账号分区选择 | 主动请求与页面监听分开；迁移时修复 PC 账号分区路由，不沿用错误行为 |
| 外部控制 | 现有 Go API 管云端业务，没有本机浏览器控制通道 | 增加本机 Socket.IO 接入及客户端主动连接的远程控制通道 |

源码依据：[Web 桥客户端](../saas-web/bridge-contract.js)、[类型契约](../saas-web/bridge-contract.d.ts)、[桥协议](saas-bridge-contract.md)、[Android 平台模块](../android-bridge/README.md)。PC 原生入口位于展开源码的 `chrome/browser/ui/webui/management/management_ui_handler.cc` 与 `chrome/browser/resources/fingerprint_manager/`，账号实际对象通过 `ManagedTabContext` 定位。

## 2. 目标架构与边界

```text
本机内嵌 SaaS → postMessage / Android MessagePort 适配器 ─┐
本机外部程序 → 本机 Socket.IO 端点 → 传输适配器 ────────┼→ 统一原生控制服务
远程 SaaS / 外部程序 → Go 控制网关                     │       ↓
                         ⇅ Socket.IO                  │  账号对象解析与权限检查
                  Chromium 原生连接模块 ──────────────┘       ↓
                                                  原生 Tab / 分区 / DevTools
```

- 统一原生控制服务属于 Chromium 本地能力层。传输适配器只处理握手、消息封装、来源或会话授权、连接生命周期，不实现另一套账号业务。
- SaaS Web 继续负责页面和同步编排；Go 继续负责登录、成员、账号授权、版本、租约和审计，新增设备连接路由与指令授权。不把登录或权限数据库复制进 Chromium。
- 本机端点服务外部调用，默认只监听回环地址，不自动开放局域网端口。远程通道由 Chromium 主动连接受信服务，连接由原生生命周期管理，不挂在 SaaS 页面脚本上。
- 内嵌 SaaS 仍依赖页面宿主，这是本方案明确保留的耦合。外部控制与 DOM/网络实现不再依赖该宿主；关闭或刷新 SaaS 不影响已授权的其他调用方。
- Android 保留 MessagePort 作为对应的本地传输，不把 Window.postMessage 当成两端相同的原生机制。
- 固定控制台、单账号单活跃 Tab 和独立持久分区保持既有产品语义，不因增加外部入口改变浏览器外壳。

### 2.1 Socket.IO 工程选型门槛

目标互通组合为 Socket.IO 4.x / Engine.IO 4，优先验证 WebSocket transport；未验证的轮询、恢复扩展或客户端功能不写入能力声明。Socket.IO 不与普通 WebSocket 互通，不能拿现有 WebSocket 接口冒充实现。[官方协议说明](https://socket.io/docs/v4/#what-socketio-is-not)

官方 C++ 客户端 3.x 声明兼容 Socket.IO 服务端 3.x/4.x，依赖 websocket++，目前只实现 WebSocket transport。它是原生主动连接的候选，不能当作 C++ 服务端使用。[C++ 客户端说明](https://github.com/socketio/socket.io-client-cpp)

Go 网关候选必须验证现代协议、二进制、ack、鉴权和维护状态；不直接采用已归档且声明仅支持 JS 客户端 1.4 的 googollee/go-socket.io。[仓库说明](https://github.com/googollee/go-socket.io)

本机 Socket.IO 服务端尚无已验证实现。先比较基于 Chromium 现有网络能力实现协议适配与可维护的原生服务端依赖，记录协议成本、线程/TLS、许可、PC/Android 接入和源码目标变化。若两者均不可行，独立本地网关仅作为架构变更候选重新评估，不默认新增 Node.js、Go 常驻进程或移动端伴随服务。远程通道可先交付，本机外部接入未通过时必须单列未完成，不能将全方案标为完成。

## 3. 统一控制契约

本表是拟新增契约，不是现有可调用 API。契约版本与 Socket.IO/Engine.IO 版本分开管理。

| 对象 | 必需信息与规则 |
| --- | --- |
| 调用身份 | 原生生成的调用方上下文、授权范围、连接代次；不接受消息自报管理员权限 |
| 请求 | protocolVersion、requestId、deviceId、accountId、environmentId、documentGeneration、method、args、有效期限 |
| 环境标识 | environmentId 是本机环境本次运行标识，与 accountId、内部 tabId、WebContents 的关系由原生登记；重开后新代次，不能当跨设备永久身份 |
| 有效期限 | 网关限制存活时间，原生收到后使用单调时钟计算本地截止时间；不只依赖两端墙上时钟一致 |
| 响应 | requestId、明确完成状态、result 或中文 message/errorCode；超时但结果未知时返回“执行结果待确认”，不冒充失败或成功 |
| 事件 | subscriptionId、环境/文档代次、sequence、事件种类、必要元数据；sequence 在订阅内递增 |
| 能力协商 | 分平台声明 DOM、子框架、Worker、网络正文、容量、事件恢复和版本；缺失能力明确不可用 |

既有 tabs/storage 等方法通过适配保持兼容，不未经评估重命名全部现有 API。新命令进入统一执行模块；兼容入口逐项转发，不复制实现。postMessage 的真实窗口/完整 Origin/文档检查继续存在，Socket.IO 使用设备身份和细粒度调用授权，两者都不能绕过原生系统权限。

### 3.1 DOM 能力

| 拟定方法 | 交付行为 |
| --- | --- |
| dom.query | 按选择器和 frameId 查询，按需返回文本、属性和 HTML，支持分页/数量上限 |
| dom.check | 判断存在、数量、可见状态、文本或属性条件；返回结构化结果 |
| dom.waitFor | 原生持有等待任务，只在满足、超时或取消时回复，避免外部高频轮询 |

底层复用 DevTools 的 DOM/Runtime 等必要能力，封装受限查询，首版不开放任意 CDP 命令或任意 JS 执行。主框架、同源/跨源子框架、Shadow DOM 的覆盖分别声明和验证；节点句柄与 frameId 绑定当前文档，导航后失效。可见判断定义 CSS、布局盒与 viewport 范围，遮挡判断另声明，不用单一 offsetParent 冒充完整可见性。[DOM 协议](https://chromedevtools.github.io/devtools-protocol/tot/DOM/)

### 3.2 网络能力

| 拟定方法/事件 | 交付行为 |
| --- | --- |
| network.subscribe / unsubscribe | 按环境、URL、方法、资源类型过滤；显式开启及释放订阅 |
| network.request / response / finished / failed | URL、方法、状态、资源类型、时序、缓存/SW 来源等事件，重定向逐跳关联 |
| network.getRequestBody / getResponseBody | 按环境、订阅、target/session、请求标识定位正文，文本与二进制分别返回 |

复用 DevTools Network 事件和正文接口。requestId 不作为全局唯一键，内部组合 target/session、订阅代次及重定向跳数；开始监听前的流量不承诺补回。跨进程 iframe、Dedicated/Shared/Service Worker 需要附加目标和所有权核对，共享或无法归属账号的目标不得广播给该账号调用方。[Network 协议](https://chromedevtools.github.io/devtools-protocol/tot/Network/)

默认推送元信息，敏感请求头和正文须单独授权，完整正文按需读取。缓存、下载、流式响应、文件上传、正文淘汰及 WebSocket 帧覆盖分别列出；无法读取时返回明确原因，不返回空正文假装成功。监听不设置绕过 SW、关闭缓存或暂停请求，不改变网站实际行为。

## 4. 并发、断线、授权与数据处理

1. 两种传输共享同一账号写操作队列、环境注册表和取消机制；请求去重键绑定调用身份、操作标识及参数摘要。同一调用方跨通道重试可查询原结果，不允许两个通道分别创建环境或交叉恢复。
2. 导航、关闭、配置和恢复等修改按环境串行；DOM 查询与网络事件可并行，但绑定文档代次。页面被替换、冻结或销毁后，旧回调不能作用于新对象。
3. 重连先重新验证授权、查询真实环境并重建订阅；不自动重放创建、关闭、导航 POST 或存储写入。ack 的“已接收”和业务“已完成”分开，进程重启后的去重记录失效须显式说明。
4. Socket.IO 默认不保证消息必达，事件补回与指令去重由应用定义。使用有界内存事件缓冲和 sequence；溢出、过期或无法续传时通知缺口，不能静默丢数据。首版不承诺进程重启后恢复全部事件。[交付保证](https://socket.io/docs/v4/delivery-guarantees/)
5. 分别设置连接、环境、订阅、未完成请求、正文缓存和事件队列额度，控制消息优先于大正文。拒绝超限并给出中文原因；正文分块携带总长度/校验、超时和释放规则，不阻塞 UI 线程。
6. Go 逐次检查用户、设备、工作区及账号权限，客户端执行前检查短期授权范围和代次；路由消息不能自报可信身份。远端撤权以设备实际获知为生效边界。退出或失权后停止对应云端控制和数据推送，保留本机 Tab 正常浏览，不清空分区。
7. 本机外部程序必须显式配对获得作用域令牌；回环地址或连接到端口本身不构成授权。内嵌桥保留现有 Origin 规则；独立本地授权不默认为退出后仍有效，是否继续由该授权的有效期与撤销状态决定。
8. 控制连接使用独立控制面网络配置，不继承被操作账号代理或网站 Cookie。远程 TLS 正常验证，禁止关闭证书校验或放宽白名单绕过接入问题。
9. 云端控制网关只处理必要路由元数据。快照明文、Cookie、密码、代理凭据、DOM 敏感内容和网络正文不在云端普通字段/日志落地；需要经云端转发的敏感载荷使用调用方到原生的加密封装，浏览器核对服务端授权的动作与目标、再解密执行。快照依旧由客户端加密，密码不因传输迁移而持久化。

## 6. 性能验证计划

“本地桥通常开销更低”是通信路径推断，当前没有本项目的比较数据。不能按协议名承诺速度倍数、毫秒或无限吞吐。

- 比较三条路径：本机 postMessage/MessagePort、本机 Socket.IO、经网关的远程 Socket.IO。均复用同一执行模块、同一真实数据和相同授权条件，不把公网延迟归因于协议编码。
- 协议传输开销单独测量，原生队列等待、DOM 执行、序列化、网络往返、回调交付分别计时。跨设备使用往返或本地单调时钟，避免未校准时钟相减。
- 测试空闲和受控页面负载下的重复 DOM 查询、原生 waitFor、双调用方并发、真实页面网络事件及正文读取。使用独立测试环境和已存在的非敏感资源，不向生产账号灌入测试数据。
- 提议负载梯度为 1/5/10 个测试环境及 1 KiB/64 KiB/1 MiB 消息；消息大小是压测输入，不是已支持上限。Android 按设备资源执行可承受梯度，超过能力时验证明确限流，不编造支持规模。
- 每条路径固定相同样本量和运行窗口，记录 p50/p95/p99、完成量、错误/超时、CPU、内存、字节量、事件缺口、队列峰值及恢复耗时；Android 补充后台和耗电基线。
- 比较开启/关闭监听时的网站加载和主线程影响。批量、过滤和按需正文策略必须在两种传输中一致，否则报告不能作为协议对比。
- A0 登记测试对象及基线，A5 首轮建立数值，再形成可复测性能门槛；关键安全用例要求零串账号/越权/过期执行，所有超限和丢失可见。未测项标为未测，不把拟定梯度当通过证据。

## 7. 验收、回退与决策

| 用例 | 必须满足的结果 |
| --- | --- |
| 两账号同站点 | DOM、请求、响应、正文、Cookie、代理不串账号；环境重开不复用旧订阅 |
| 双通道并发 | 同账号重复创建幂等；写入不交叉；重试可核对真实结果，不能凭超时重新执行 |
| 导航/关闭/换对象 | 旧节点、frame、请求正文及等待任务拒绝或取消；跨源新文档须重新绑定 |
| 断线/重连/慢消费者 | 有界内存、缺口通知、重新授权；不自动重放副作用，不阻断网站网络 |
| 来源/权限 | 非法 iframe、未配对本机程序、错误设备/账号/过期授权和跨订阅正文读取均被拒绝 |
| SaaS 生命周期 | 刷新只取消自身文档任务；退出/撤权停止对应云端指令及推送，已打开 Tab 继续浏览 |
| PC/Android 生命周期 | Windows 最新 Release 运行通过；Android 前后台、冻结、Activity 重建、进程回收后安全重连，不恢复旧授权 |
| 原有同步与系统能力 | 选择类别、客户端加密、版本/租约、指纹回读、SAF/Keystore/文件授权行为不变且真实回归通过 |

实施失败时按阶段停用新 capability 和连接入口，保留旧桥、账号分区、密文及历史记录；历史文件如需移除只放回收站，不删除构建缓存。未经授权不修改任何编译参数；必要参数变更先报告旧值/新值、平台/输出及重编译源文件/编译单元和生成/链接目标估算。Android 构建仅在已核实的 WSL Linux 工具链内执行，本次文档任务不运行 GN/Ninja。

本方案适合优先保留当前本机交互、逐步开放外部控制。代价是维护两个传输适配器与跨通道并发，内嵌 SaaS 仍依赖宿主。两种适配器都直接进入同一控制服务是交付条件，不能出现 Socket.IO 绕回 SaaS 页面再触发 postMessage 的链路。
