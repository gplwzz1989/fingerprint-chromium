# 跨平台指纹浏览器开发规则

更新日期：2026-10-05。适用范围：独立 SaaS、Chromium 共享引擎、Windows 客户端及 Android 客户端。

本文把长期开发约束和交付要求集中维护。产品范围与现状见 [项目总览](../PROJECT-OVERVIEW.md)，任务顺序见 [开发计划](development-plan.md)。根目录 [AGENTS.md](../AGENTS.md) 是代理执行入口，编译参数强制锁继续完整有效；本文不授予参数变更、全量构建、工具安装或发布许可。

## 1. 开发入口与文档职责

每次任务先读总览第 1、2、5 节，再读本规则、开发计划中的相关任务与目标模块协议。先确认运行版本、真实调用链和已有未提交变更，再修改文件。

| 文件 | 维护内容 | 更新时机 |
| --- | --- | --- |
| `PROJECT-OVERVIEW.md` | 产品目标、架构、当前能力与验证边界、风险、导航 | 整体状态、产品范围、模块边界变化时 |
| `docs/development-rules.md` | 长期开发、数据、安全、验证和交付约束 | 开发机制或已确认产品约束变化时 |
| `docs/development-plan.md` | 当前优先级、任务依赖、交付物、验收条件、阻塞 | 开始、结束、阻塞或调整一个任务时 |
| `docs/implementation-status.md` | 有日期的变更、验证结果、失败和跳过原因 | 每个可交付阶段结束时，在顶部追加记录 |
| `docs/saas-bridge-contract.md`、`docs/saas-account-sync.md`、`docs/saas-api.openapi.yaml` | 具体桥、同步、API 字段与行为 | 对应行为改变时与代码同批更新 |
| `docs/managed-tab-roadmap.md` | 原有分阶段路线与历史目标 | 保留历史事实；当前执行顺序引用开发计划 |

同日记录也须标明验证对象与范围。文档中的“当前”以最近一次实际核对为准，不能把历史测试、旧二进制和最新源码混为一个状态。发现冲突时核对代码、实际参数与产物，修正文档；不能按文档猜测并覆盖运行配置。

## 2. 修改归属

| 行为 | 主要修改位置 | 必要联动 |
| --- | --- | --- |
| 页面、移动布局、账号流程、同步编排、会话交互 | `saas-web/` | API 或桥语义变化时更新契约 |
| 登录、角色、账号授权、版本、租约、密文、审计、配额 | `saas-server/` | PostgreSQL 迁移、API 与前端 |
| Windows 窗口、原生 TabStrip、宿主、系统文件与原生网络 | 对应 Chromium 源码和 `patches/` | SaaS 调用和能力声明按需要更新 |
| Android 主框架端口、TabModel、JNI、SAF、Keystore、生命周期 | `android-bridge/`、展开源码和对应补丁 | Android 源清单、公共契约、前端 |
| 分区、渲染器、网络、Blink、Worker 指纹 | 实际共享引擎与平台接入点 | 分别核对 Windows 与 Android 注入、构建及效果 |

已有桥能力足够时只修改 SaaS。历史 WebUI 的业务代码属于兼容资产，不再新增登录、成员、账号目录、同步或计费业务。Android 不复制第二套 SaaS，也不照搬 Windows 窗口、路径或构建参数。

PC 的 `ManagedTabContext` 实现还分布于 `chrome/browser/ui/browser_tab_strip_model_delegate.cc` 等文件，Android 的枚举入口在 `managed_tab_context_android.cc`。定位不能假定所有实现都在同名独立 `.cc` 中；须追踪定义、条件编译、调用方与源清单。

## 3. 最小修改与可恢复性

1. 保留现有中文注释、描述、未修改代码和用户未提交变更。只改任务相关区域，现有文件原地修改，不删除后重建，不做无关格式化或重构。
2. 文件少于 50 行、用户明确要求或原文件无法维护时才考虑完整重写，并说明原因。大文件分区域修改。
3. 文本使用 UTF-8，优先无 BOM；用户界面、API `message`、用户错误和用户日志使用简体中文。开发者诊断与协议标识可以保留必要英文。
4. 不新增无关依赖、重复工具或未经要求的业务入口。不用 Mock、随机数据、假 Tab、假接口或假成功替代真实实现；测试探针限定在明确的测试目录，不进入运行包。
5. 历史文件、旧包和临时文件需清理时先核对引用、运行占用及绝对路径，移入回收站；禁止永久删除。WSL/Linux 场景无可靠可恢复机制时先保留文件，不使用永久删除替代回收站。
6. 完整保护 `build/`、`publish/`、源码、构建图、对象、生成文件、依赖记录、工具链、下载及编译缓存。禁止删除 `obj/`、`out/`、`.ninja_deps`、`.ninja_log`，禁止重解包源码掩盖增量问题。

## 4. 账号与环境不变量

- `user_id` 表示 SaaS 用户，`workspace_id` 表示业务工作区，`account_id` 表示稳定业务账号；`tab_id` 是本机运行对象，`device_id` 是设备会话身份，`revision` 是云端快照版本。不同标识不能相互代替。
- 同一客户端同一账号最多一个活跃环境；该限制不是“全球只能一台设备运行”。云端编辑租约约束快照提交，不应当被描述为浏览器运行独占锁。
- 账号创建、恢复、普通关闭再打开与正常重启保持分区身份；禁止退回共享默认分区、通过清空共享 Cookie 或使用无痕模式替代隔离。启动 URL 和指纹在首次业务导航前确定。
- Cookie、LocalStorage、SessionStorage、IndexedDB、Cache Storage、Service Worker、网络上下文、渲染器配置及历史路径须按真实机制核对隔离，不能以 Cookie 单项通过证明整体隔离。
- 唯一常驻控制台不能进入账号操作列表、快照或批量关闭。桌面单父窗口与 Android Activity/TabModel 使用各自机制；应用正常退出不受控制台关闭保护阻碍。
- 云端目录、设备会话与运行 Tab 分别查询。打开失败不能显示运行中，超时不能返回成功；过期请求不能影响新登录、新工作区、新文档或替换后的 WebContents。
- 产品级跨平台兼容和退出/撤权策略以总览已确认决策为准。未实现的策略记作开发任务，不能把规则写入文档就宣称运行保护已生效。
- 退出 SaaS、设备会话被撤销或账号失权后停止旧身份的 SaaS 云端业务，已打开的本机账号 Tab 继续浏览、导航及网站网络访问，不自动关闭或清空本地分区。取消在途同步/恢复的后续动作不能误伤独立浏览；原生 Origin、文档代次和 SAF 等系统授权仍独立校验，不因保留 Tab 而放宽。

## 5. 指纹与代理验证

指纹验收包括三层：输入与配置回读、页面/Worker 可见值、真实网络请求。修改 UA、UA-CH、硬件值、指纹种子或代理后，分别记录两端实际效果。

必须检查页面、跨来源子框架、Dedicated/嵌套/Shared/Service Worker，覆盖 Worker 创建前后配置变化、受控重载和账号切换。网络检查使用服务端实际收到的 UA/UA-CH 与出口，不仅查看界面或客户端参数。`worker_fingerprint_verified=false` 在有效验收前不得改为 true。

Canvas、WebGL、Audio、字体、时区等基础补丁不自动证明已具备账号级控制或两端一致性。先形成“参数来源—应用位置—平台能力—检测结果”矩阵，再承诺支持。系统平台、GPU、屏幕、字体与请求头相互矛盾须显式暴露，禁止静默伪造兼容。代理失败、认证失败及重定向须检验是否发生直连回退、Cookie 串用或凭据跨来源泄漏。

用户进一步明确：PC 与 Android 指纹参数应完整兼容，统一字段、范围、默认语义与恢复方式；某端缺失要修复实现，不提供平台降级方案。选中指纹类别时按快照原值恢复，恢复前校验格式和原生能力，应用后回读核对；不允许替换 UA、丢弃字段或调整种子。未选类别保留本地配置，恢复范围取云端内容与操作开始时选择的交集。Worker 验收标记不能成为业务阻断；参数回读与页面/网络/Worker 效果各有验收边界，后者仍须逐端验证。

同步登录数据不保证第三方网站允许跨设备复用登录态；设备绑定、服务器撤销和风控导致重新登录时展示真实结果，不用注入假状态宣称恢复成功。

## 6. 同步、版本与故障语义

当前同步类别是 Cookie、LocalStorage、SessionStorage、指纹、代理和页面地址；IndexedDB、Cache Storage、Service Worker 仅列为本地隔离目标，未完成同步设计与实现前不能纳入支持清单。

- 上传流程：权限与上下文检查 → 原生读取所选类别 → 校验账号/来源 → 客户端加密 → 获取短期编辑租约 → 按明确版本提交 → 展示真实结果 → 尝试释放租约。
- 恢复流程：读取受授权的密文 → 解密并核对账号/格式/兼容性 → 准备隔离空白环境 → 应用配置 → 按来源建立存储上下文 → 写入所选类别 → 受控刷新并验证实际效果。具体当前流程以 `snapshot-sync.js` 为准；网站导航与存储恢复的先后风险必须实测。
- 未选择类别不上传、不清空也不覆盖本地数据。网页存储须绑定来源；不同来源不能直接合并。冲突处理的本地优先规则须保持契约一致。
- 默认不覆盖新版本；明确覆盖仍提交刚读取的具体版本。服务端拒绝 `If-Match: *`，不能把前端安全行为等同于服务端强制规则；直接 API 调用也必须经过具体版本检查。
- 云端租约、数据库行锁与本机串行队列各自承担不同一致性职责。同步/恢复超时、失权或退出后停止该操作的后续云端业务请求及本地恢复副作用，保留已打开 Tab 的独立浏览；必要会话撤销与租约清理按真实授权和结果处理，清理不可完成时等待租约到期。“清理失败”不能把已成功提交改报失败。
- Cookie 与网页存储恢复不是整体原子事务。导航、配额、IPC 或撤权导致部分写入时明确提示，不宣称全部回滚；重试前重新读取状态，不自动重放页面 POST 或盲目重复提交。
- 断网与 401/403 分别处理。断网不能冒充退出成功或权限已确认；401/403 不能无限重试。会话刷新、账号切换、工作区切换使用代次检查，旧响应不得重新写回凭据或解锁状态。

## 7. 安全与权限

1. Go 对每次业务请求验证会话有效性、工作区角色及账号授权；原生宿主对每次能力调用验证真实主框架/消息来源、完整 Origin、文档代次和平台授权。两层各自必需，服务端 CORS 不授予原生权限。
2. 生产高权限页面与 API 使用 HTTPS。服务部署地址、前端 API 根地址、默认启动 URL、PC/Android 原生白名单、CSP/嵌入策略必须一致；不得用 `*`、任意来源或关闭 TLS 校验解决联调。
3. 云端只保存客户端加密的环境信封及必要元数据。快照密码与登录密码分离，当前页面内存持有快照密码，不写日志、不持久化；不能把登录密码重置当作已实现的快照恢复能力。
4. Android Keystore 的本机刷新凭据不可同步到另一设备；桌面 `secureStorage` 当前未接入。普通浏览器/桌面现有 SessionStorage 过渡行为须如实记录，不承诺等同 Keystore 保护。
5. 快照密文与安全会话存储不等于整个本地账号分区已加密。本地磁盘、备份及同机用户隔离须单独评估，不宣称已防止本机读取或已离线撤销数据。
6. SAF 使用用户授权的目录树与相对路径；Windows 文件接口仍受进程权限和来源白名单约束。新增高权限能力需定义路径、容量、并发、超时、撤权、覆盖与失败语义。
7. 原生 HTTP 默认不带 Cookie；携带凭据时绑定真实账号分区。重定向、代理认证、敏感头、TLS 与响应上限遵循各端契约；不能因 PC 上限较大而向 Android 发送不兼容请求。
8. 日志和审计只记录必要的对象标识、动作、结果和错误码，不包含令牌、密码、Cookie、存储明文或代理凭据。完整性要求涵盖服务端、网页、原生和导出；目前未上报的本地动作须记作缺口。

角色与显式分配的现有语义须特别保留：账号无显式成员时对工作区成员开放；删除最后一条显式分配会恢复开放。若要改变为“仍保持私有”，需先确定产品语义、迁移旧数据并联动列表/授权接口与 UI，不以隐藏按钮替代服务端控制。

## 8. 原生源码与补丁一致性

修改 Chromium 时最小更新 `build/src/` 对应源码及可重放补丁；Android 平台模块、展开源码和持久补丁同步，新增补丁加入 `patches/series`。禁止只修被 Git 忽略的展开源码。

检查按顺序进行：补丁格式 → 顺序/上下文 → 已展开源码与持久副本一致 → 在独立验证工作区重放 → 目标平台编译 → 运行效果。独立重放不得覆盖现有工作区或重新解包当前 `build/src/`；所需额外磁盘/源码准备单独评估。`git apply --numstat` 成功只证明格式，反向检查只证明当前上下文可逆，两者均不能代替完整顺序重放。

共享引擎改动按实际文件与构建分支评估两端。每个平台声明真实可选能力、额度和版本；不可用能力明确返回中文错误，不能提供空实现假装成功。破坏性桥变更递增主版本，快照格式使用自己的 `schema_version`，不混用两种版本。

## 9. 构建参数与平台执行强制约束

### 9.1 PC 与 Android 同等适用的参数锁

编译参数默认锁定。范围包括 `build-configs/*.gn`、`build-roots.json`、实际 `args.gn`、展开配置副本、工具链/SDK/NDK/JDK 版本和路径、改变编译命令的环境变量、全局宏、公共 GN、优化/链接/组件配置。不得通过脚本覆盖、自动探测、创建新输出或切换模式绕过。

优先修复出错源码、目标、平台适配或补丁。确需改参数，实施前提交：根因；已核对局部方案及不足；必要性；平台/输出；旧值/新值；预计重编译源文件/编译单元数量或区间；可统计的生成/链接目标数量；只读估算依据与不确定性。只有时间、对象文件总数或 Ninja 步骤数不满足要求。

评估不能先改参数、GN 重生成或编译后补报；Ninja 干跑前确认不会执行生成器。无法可靠统计时明确未知和有依据的保守范围，失败或无输出不能写成零。用户针对本次方案确认后仅实施已批准范围；新的参数差异、平台或影响范围扩大时重新确认。

历史告警处理确认仅是已存在的配置事实，不授权进一步全局禁用检查、删功能、换工具链或重编译。模板与实际参数现有差异原样保留，内容未变不覆盖文件或更新时间戳。具体强制锁以 `AGENTS.md` 完整条款为准。

### 9.2 构建执行

- SaaS、文档和设计修改不得触发 GN 或 Chromium 编译。原生普通源码修改先做必要的局部静态检查或最小目标；GN 输入真的变化时才评估重生成。
- 所有编码任务完成前不启动 `chrome`/Release 全量构建。全量构建前报告参数、构建图和预计范围，获得用户明确要求；参数许可不自动授权全量编译、缓存清理或工具安装。
- PC 当前只使用 Windows x64 Release 活跃配置，复用 D 盘 Visual Studio、Windows SDK、Clang、临时目录及 `DEPOT_TOOLS_WIN_TOOLCHAIN=0`、`PYTHONUTF8=1` 的已有环境。Development 仅保留历史输出，不重新提供活跃入口。
- Android GN/Ninja、SDK/NDK/JDK、Gradle、APK/AAB 均在 WSL Linux 执行。先只读确认发行版 Running、实际 Linux 工具可执行及版本、源码完整性、ABI、构建图和独立输出/缓存。存在目录或脚本启动器不证明工具可用；阻塞时停止相关构建，不改用 Windows 工具链、不自动安装。
- Windows 和 Android 独立输出，历史 Development 独立保存。Android 平台构建与适配不是逆向任务，不读取或调用逆向工具链。

### 9.3 日常开发标准作业流（SOP）

按以下顺序判断和执行，作为日常开发的默认路径：

1. 需求分类：业务、界面、鉴权或逻辑修改放在 `saas-web/` / `saas-server/`，不触发 GN 或 Chromium 编译。
2. 必须修改 Chromium 原生实现时，默认只改受影响的 `.cc` 文件，不改公共 `.h`，不碰 `args.gn`、`common.gn` 或其他公共编译参数。若任务确需修改公共头文件、平台专属非 `.cc` 文件或编译配置，先按本节参数锁提交原因、局部方案不足、平台/输出、旧值与新值及预计影响，并取得本次明确确认。
3. 单文件修改后先运行 `python -X utf8 utils/check_cpp_syntax.py <相对 build/src 的 .cc 路径>`，进行约 2～5 秒的拼写和语法排查；该检查不替代目标构建、链接或真实运行验收。
4. 构建前对明确的受影响目标运行 `ninja -n` 进行范围预检：
   - 超过 10 步：立即排查头文件依赖泄露或无关依赖扩散，必要时回滚本次重构并缩小修改范围；
   - 仅 1～5 步：范围预检安全通过；
   - 处于 6～10 步、目标不明确或出现生成器动作：暂停执行，重新核对依赖和构建目标，不把未知范围当作安全通过。
5. 范围确认后执行实际目标构建时显式限制并发为 `ninja -j 4`，避免占满物理内存。Windows 使用现有 PC Release 输出；Android 的 GN/Ninja 必须在 WSL Linux 的独立输出目录执行。

这套 SOP 只规定日常局部修改和增量构建的默认顺序，不解除第 9.1 节的参数锁、全量构建前置确认、平台隔离和构建产物保护要求。

## 10. 验证层级与完成定义

| 状态 | 必需证据 | 不能替代的下一层 |
| --- | --- | --- |
| 已编码 | 可定位的源码、补丁、契约与能力声明 | 编译或运行 |
| 局部验证通过 | 检查/测试命令、结果、对象、跳过与限制 | 最新平台集成 |
| 平台构建通过 | Windows 程序或 Android 目标编译/链接/包及来源信息 | 原生运行效果 |
| 运行验收通过 | 对应最新产物、设备、真实页面/网络/数据链路及负向场景 | 安装升级与发布 |
| 可发布 | 兼容性、真实闭环、安全、安装升级、备份回滚与必要容量验证 | 后续版本稳定性 |

同一模块可以“已编码、局部通过、运行未验收”，不能用百分比掩盖缺口。累计历史测试数量不代表最近源码复测；Go 缓存结果须如实注明；JVM、JNI 生成或借用桌面参数的 C++ 检查不能记作 Android 完整编译。

| 修改范围 | 最小验证 | 升级到运行验收的条件 |
| --- | --- | --- |
| Web 行为 | 相关 JS 语法及已有相关回归 | 桥/同步/权限交互变化需真实接口和客户端联调 |
| Go/API/迁移 | 相关测试、`go vet`；数据库行为使用独立测试库 | 权限、版本、租约变化需真实 PostgreSQL 并发/撤权场景 |
| 桥契约 | Web 类型/调用、消息与来源负向测试、各端能力声明 | 受影响平台最新产物逐端验证 |
| 原生存储/网络/指纹 | 对应源码与补丁、最小目标检查 | 真实分区、页面、网络及 Worker；必须标明产物版本 |
| Android 系统能力 | 协议检查与实际 Android 类型/JNI/C++ 构建 | 真机/目标设备权限、进后台、进程回收与撤权 |
| 仅文档 | 本地链接、术语、事实、状态与差异检查 | 不要求为文档重新构建浏览器 |

不为低影响修改添加镜像实现式测试，不无条件重复全套测试。数据库集成不得使用生产库，缺少 `SAAS_TEST_DATABASE_URL` 明确标为跳过。首版原生闭环完整验收清单见开发计划。

## 11. 发布与持续迭代

每次迭代限定一个可验收目标，依次完成定位、最小实现、相关验证、契约更新和阶段记录。发现环境阻塞继续推进不依赖该环境的工作，不用扩大重构或参数调整掩盖阻塞。

Chromium 基线、上游安全修复、Go 依赖和 Android 平台兼容性须持续跟踪。内核升级作为独立任务评估补丁重放、桥/快照兼容、两端构建范围和回归，不直接替换现有工作区或工具链；紧急安全问题按实际影响提高优先级，不能永久以闭环开发为由搁置。新版本状态先核实来源，不拿上游发布表当本项目已升级的证据。

发布分三类：SaaS 静态页面/Go 服务、Windows Chromium、Android APK。各自记录提交/工作区差异、内核与契约版本、参数指纹、产物哈希、测试日期和验证平台。版本清单不得包含秘密。

SaaS 使用 `utils/package_saas.ps1`，沿用固定 `-OutputPath`，项目归档放 `output/`；成功新包替换同一路径，旧包移入回收站。此包不更新 PC 内核或 APK。Windows 安装包与 Android 签名/升级策略尚待实现，不写成已有功能。

数据库迁移记录兼容范围、失败恢复与回滚方案；优先先兼容读写再切换，避免新旧客户端同存期间丢失数据。客户端遇到不兼容服务或快照应明确拒绝危险动作。回滚不得丢弃已有账号分区、云端密文版本、审计或 Keystore 数据。

阶段记录至少包含：任务标识、变更文件、真实行为、验证对象/版本、通过/失败/跳过、已知风险、未完成项和下一任务。面向用户的完成汇报只给主要结论、文件及验证边界。
